# Vuesp Interface Design

Практический скилл для интерфейсов Vuesp: веб, мобильные приложения и промышленные панели. Основан на подборке актуальных практик 2025–2026 и правилах проекта.

## Когда применять

- новая страница, экран, панель или компонент;
- редизайн или UI-ревью существующего интерфейса;
- таблицы, формы, диалоги, фильтры, навигация;
- dashboard, карточки, статусы, алерты;
- HMI/SCADA, панели оператора, мобильный мониторинг;
- проверка доступности, контраста, адаптивности.

## Первый шаг

1. Определи контекст: **web**, **mobile**, **industrial** или смешанный.
2. Прочитай `references/principles.md` — сквозные принципы.
3. Открой нужный reference:
   - `references/web.md`;
   - `references/mobile.md`;
   - `references/industrial.md`.
4. Сверься с `references/project-rules.md` — правила Vuesp, Tailwind и компонентов.
5. Составь короткий чеклист под задачу и только потом правь код.

## Сквозные правила

- Доступность — базовый стандарт: WCAG 2.2, контраст, клавиатура, ARIA, скринридеры.
- Один экран — одна основная задача. Прогрессивное раскрытие вместо перегруза.
- Цвет не единственный код состояния: цвет + иконка + текст.
- Тёмная и светлая темы проектируются вместе; проверяй обе.
- Все состояния: loading, empty, filled, error, disabled.
- Обратная связь на действие — быстрая и тихая.
- Mobile-first; проверяй от 320 px.
- Тестируй на реальных устройствах, а не только в эмуляторе.

## Правила Vuesp

- Стилизация — только Tailwind-утилиты в разметке.
- Отступы, паддинги, маржины и `gap` — по шкале, кратной 4 px.
- Карточки — только `VCard` из `vuesp-components`.
- Кнопки — `VButton`; ссылки — `NuxtLink`; иконки — `VIcon`.
- Иконочные кнопки — с `aria-label` и `title`.
- Типы: интерфейсы `I*`, type-алиасы `T*`.
- Не добавляй произвольные цвета, размеры и `style`, если есть токен/утилита.
- Не дублируй компоненты кита локальными копиями.

Подробно — в `references/project-rules.md` и `../vuesp-workspace/docs/code-rules.md` (если workspace доступен).

## Чеклист перед «готово»

- [ ] Понятна иерархия и основное действие экрана.
- [ ] Все состояния продуманы: загрузка, пусто, данные, ошибка, disabled.
- [ ] Контраст и клавиатурная навигация проверены.
- [ ] Иконочные кнопки имеют `aria-label` и `title`.
- [ ] Цвета и отступы — из токенов/шкалы, без произвольных значений.
- [ ] Карточки — `VCard`; нет ручных `glass-inset`/`rounded-[10px]`.
- [ ] Мобильная версия проверена, нет горизонтального переполнения.
- [ ] Тёмная и светлая темы проверены.
- [ ] Нет дублирования компонентов и логики.
- [ ] Для HMI: авария отличается цветом, формой и текстом; нормальное состояние не мигает.

## Что не делать

- не собирать карточки и панели вручную из `bg-*`, `border-*`, `p-*`;
- не использовать `text-[11px]`, `p-[13px]`, `gap-[7px]` без причины;
- не прятать основную навигацию в гамбургер на мобильном;
- не делать цвет единственным индикатором состояния;
- не добавлять анимацию/мигание в нормальном режиме HMI;
- не копировать компоненты кита в приложение.

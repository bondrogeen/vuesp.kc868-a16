# Сквозные принципы

Общие для веба, мобильных приложений и промышленных интерфейсов.

| Принцип | Суть |
|---|---|
| **Доступность — базовый стандарт** | WCAG 2.2, контраст ≥ 4.5:1 для обычного текста и ≥ 3:1 для крупного, клавиатурная навигация (Tab/Shift+Tab, Enter, Esc, стрелки), ARIA-метки, скринридеры (VoiceOver/TalkBack), динамический размер шрифта, цвет не единственный код состояния. |
| **Минимизация когнитивной нагрузки** | Показывать только нужное сейчас. Иерархия информации, прогрессивное раскрытие, один экран — одно основное действие. |
| **Производительность — гигиена** | Лёгкие ресурсы, скелетоны вместо спиннеров, SVG для иконок, WebP/AVIF для фото, минимум запросов. |
| **Dark-first** | Тёмная и светлая темы проектируются параллельно. Особенно важно на OLED и в цеху. |
| **Единая дизайн-система** | Токены цвета, типографики, отступов, радиусов, теней и движения. Переиспользуемые компоненты, консистентность веб + мобильных + HMI. |
| **ИИ и адаптивность** | Интерфейс подстраивается под контекст, но критические решения остаются за человеком (human-in-the-loop). |
| **Микро interactions со смыслом** | Быстрая, тихая обратная связь на действие. Отвечает на вопрос «что только что произошло?». |
| **Тестирование на реальных устройствах** | Эмуляторы не заменяют телефоны, сенсорные панели и реальные условия цеха. |
| **Состояния** | Каждый экран: загрузка, пусто, заполнено, ошибка, disabled. Ошибка объясняет, что случилось и что делать. |

## Универсальный чеклист

- [ ] Понятна основная задача экрана.
- [ ] Есть визуальная иерархия: заголовок → основное → вторичное.
- [ ] Все состояния продуманы.
- [ ] Контраст и клавиатура проверены.
- [ ] Иконочные действия доступны с клавиатуры и имеют подписи для скринридера.
- [ ] Нет перегруза декором и лишней анимацией.
- [ ] Проверено на узком экране и в обеих темах.

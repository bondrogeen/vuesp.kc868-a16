# Правила проекта Vuesp

## Стили и вёрстка

- Стилизация — только Tailwind-утилиты в разметке.
- Отступы, паддинги, маржины и `gap` — по шкале, кратной **4 px** (`1` = 4 px, `2` = 8 px, `4` = 16 px).
- Не использовать `p-[13px]`, `mt-[22px]`, `gap-[7px]` без реальной необходимости.
- `<style>`/CSS — только для сложных SVG-анимаций, `@keyframes`, вычисляемых CSS-переменных и сторонних компонентов без проброса `class`. Причину фиксировать комментарием.
- Не дублировать утилиты кастомными классами.

## Карточки

- Только `VCard` из `vuesp-components`.
- Не собирать карточки вручную из `glass-inset`, `rounded-[10px]`, `border-*`, `bg-*`, `p-*`.
- Поверхности: `glass` — основная, `solid` — модалки/auth, `outline` — вложенные, `ghost` — прозрачные обёртки.
- Радиус карточек — `rounded-xl` (12 px), вложенных элементов — `rounded-lg` (8 px).
- Паддинг карточки — `none` или `lg`; остальное — классом на внутреннем блоке.
- `hover` — только для кликабельных карточек.
- Если нужен новый вариант — обсуждать добавление в `VCard`, а не собирать локально.

## UI и иконки

- Где действие однозначно (добавить, обновить, сменить вид, открыть, закрыть, поиск, настройки) — кнопка-иконка с `aria-label` и `title`.
- Текст оставлять для неоднозначных и деструктивных действий: удалить, отправить, оплатить, подтвердить.
- Иконки — из `VIcon`; если нужной нет, добавить в общий набор.
- Нативные `<button>`/`<a>` в приложениях не используем: `VButton` и `NuxtLink`.
- Фокус: `focus:outline-none focus:ring-2 focus:ring-…`.
- `VSwitch`/`VBadge` могут отсутствовать — использовать доступные компоненты кита и токены.

## Типы

- Интерфейсы — `I*`, type-алиасы — `T*`.
- `type IFoo` и `interface TFoo` — ошибка; исключения — аугментации и generated-типы.
- Локальные типы — в `types.ts` рядом с компонентом; общие — в `src/types`.
- Только `import type` для типов.
- `strict: true`, без `any`: `unknown` + сужение.

## Компоненты и слои

- Приоритет — `vuesp-components`; локальная копия только если аналога нет.
- Общие продуктовые композиции — в `layers/ui`.
- Блок не читает устройство/WebSocket/API сам: данные приходят через провайдер/контекст.
- Резолверы и преобразования — чистые функции; побочные эффекты — на границах.
- Дублирующую разметку/логику выносить в компонент, composable или функцию.

## Цвета и тема

- Источник цветов — `vuesp-components/src/assets/theme.css`.
- Новый цвет — сначала токен в UI kit, потом использование.
- Запрещены `bg-[#...]`, `text-[#...]`, `border-[#...]`, hex в `<style>` и inline-стилях.
- Использовать утилиты токенов: `bg-cyan-main`, `text-slate-main`, `border-night-light-10`, `shadow-blue-glow`.
- Прозрачность — `/10`, `/80` или `color-mix`, не новый rgba.
- Брендовые цвета — только токены; Tailwind-палитра — для нейтральных/семантических состояний.

## Типографика

- Размеры — только из шкалы Tailwind: `text-xs`, `text-sm`, `text-base`, `text-lg`, `text-xl`, `text-2xl`.
- Насыщенность — `font-normal`, `font-medium`, `font-semibold`, `font-bold`.
- Без `text-[11px]`, `text-[0.92em]`, `font-[550]`.
- `tracking-*` — только для заголовков/капса.

## Доступность и адаптивность

- Mobile-first; проверка от 320 px.
- Семантика: `header`, `nav`, `main`, `section`, `article`, `input`.
- `aria-label`/`title` для иконочных кнопок.
- Состояния `hover:`, `active:`, `disabled:`, `focus-visible:`.
- Проверять переполнение: длинные слова, таблицы, тултипы, кнопки.

## Как применять

1. Перед UI-задачей прочитать этот файл и нужный reference.
2. Составить чеклист для конкретного экрана.
3. Реализовать на компонентах кита и Tailwind-утилитах.
4. Проверить состояния, доступность, мобильную версию и обе темы.
5. После изменений кода обновить graphify, если репозиторий входит в граф.
